# @deepseek-ai/dsh-api-jev-router

English | [中文](README.zh.md)

## Summary

The `jevRouter` Remote asks the Jev decision model how complex a prompt is and switches the Session's next model step to the matching configured tier. The browser calls `route` before it submits a prompt in automatic model mode; the server applies no mode of its own.

<a id="use-this-package"></a>
## Use this package

Configure `tiers` in `cordis.yml`, ordered easiest to hardest; index = tier. Routing needs at least two tiers and a credential named by `apiKeyEnv` (default `OPENROUTER_API_KEY`, resolved through the credentials service or the launch environment on every call). Without either, `route` returns `{ routed: false, reason: 'disabled' }` and the plugin stays inert.

`route({ sessionId, text })` asks Jev for one score over one level per tier. The highest-probability level wins; when Jev's confidence is below `minConfidence` (default `0.6`), the router steps one tier up, capped at the hardest tier. A result of `routed: true` carries the tier and the selected route. `unchanged` means the Session already uses that route. `jev-unavailable` means Jev failed, timed out, or answered in an unexpected shape; the current model stays. An unknown or inaccessible Session rejects with the Session error.

`endpoint` and `model` default to OpenRouter's Decisions API and `typesafe/jev-1.14`. `timeoutMs` (default `3000`) bounds the Jev call. `maxChars` (default `8000`) keeps the last characters of a long prompt.

<a id="understand-the-implementation"></a>
## Understand the implementation

<details>
<summary>Maintainer details — click to expand</summary>

The Remote resolves the Session Agent through `sessionController.resolveAgent`, the same path as the Session Remote. It validates the selected route with `llm.resolveCallConfig` and then records it with `agent.model.select`, which appends a `model/selection` event. It does not call `session.selectModel`, which would also persist the default for new Sessions.

`src/jev-client.ts` builds one `score` question named `complexity` with one criterion per tier and reads the `answers.complexity` fields `probabilities` and `confidence`. The wire format is unverified against a live key; see the `shortcut:` note in that file. `src/policy.ts` holds the pure tier choice and the prompt truncation.

Every failure of the Jev call — network error, timeout, non-2xx status, or response that does not parse — yields `jev-unavailable`. A caller cancellation still rejects.

</details>

<a id="model-experience"></a>
## Model Experience

### Request context and condition

#### What the model sees

When a switch happens, the next model step runs on the selected route, and the Agent adds one user message before that step. The message is the existing model-switch notice, generated by the Agent, not by this package; `{from}` and `{to}` are the previous and selected routes, and the provider is omitted when both routes share it.

##### Model-switch notice text

```markdown
[model changed: assistant turns above this point were generated by {from}; the session continues with {to}]
```

#### Token effect

The notice adds one short user message per switch, plus the route labels. The Jev call uses tokens of the Jev model and never enters the Session's model request.

#### KV Cache effect

A switch changes the model request header, so the previous route's cached prefix cannot be reused for the next step; the notice appends after that history. Routing that selects the current route, or a disabled or unavailable router, leaves the Session's request unchanged. The Jev call is an independent request and does not change the Session's cache.

## Known Limitations and Deferred Work

- **Subagent, schedule, and ACP prompts bypass routing** — only the browser calls `route`; delegated subagents, scheduled follow-ups, and automation-only ACP submissions use the Session's current model.
- **Image prompts are not checked** — `route` receives text only. A tier whose model cannot read images may receive an image prompt once a switch selects it.
- **Prompt text leaves the deployment** — `text` is sent to the configured Jev endpoint, a third party when the default OpenRouter endpoint is used, and is truncated to `maxChars` keeping its tail.
- **Tier criteria come from `description`** — Jev scores against each tier's `description`; a tier without one is sent as `Tier <index>`, which carries only its order.
